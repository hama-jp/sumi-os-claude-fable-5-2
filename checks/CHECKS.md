# 主担当の検査項目(2026-11-10、走らせる前に固定)

成果物を別フォルダーへコピーして凍結(SHA-256)し、QEMU を QMP で操作して確かめる。モデルの自己申告は採点に使わない。コードは直さない。

| # | 完了条件 | 確かめ方 | 合格 |
|---|---|---|---|
| 1 | build.sh / run.sh | 生成物を消した複製で `./build.sh` → `./run.sh` | エラーなくイメージができ起動する |
| 2 | ログイン画面 | 起動後の screendump の解像度と画面。誤ったパスワード→正しいパスワードの順に入力 | 1024x768 以上。誤りでは入れず、正しいと入れる |
| 3 | ウィンドウ操作 | QMP のマウス入力で、2枚以上開く・タイトルバーをドラッグ・後ろの窓をクリック・閉じる。各操作の前後を撮る | 位置が変わる、前後が入れ替わる、閉じる |
| 4 | アプリ4つ以上 | ターミナルでコマンドを8種類実行。エディタ、ファイルマネージャ、もう1つを開く | 4つ以上が動き、コマンド8種類が応答する |
| 5 | 永続化 | エディタで検査用の文字列(その場で決める乱数入り)を保存 → QEMU を終了 → 再起動 → ファイルマネージャとターミナルで読む | 両方から同じ内容が読める |
| 6 | 同時実行 | 時計かアニメーションを出したまま別窓に入力し、数秒おきに2枚撮る | 入力が反映され、かつ時計・アニメーションも進む |
| 7 | 時計 | 画面の時刻とホストの時刻(UTC/JST)を比べる | 時差の取り方を除き1分以内 |
| 8 | 30分の連続操作 | 開く・打つ・保存・閉じるを QMP スクリプトで30分繰り返し、最後に入力が通るか見る。異常時の表示はソースで該当処理を読み、可能なら実際に起こす | 30分後も操作に応答。異常の原因を画面に出す処理がある |
| 9 | README | 構成・起動・ログイン・操作・既知の不具合の記載。書いてある不具合と、検査で見つけた不具合を突き合わせる | 5項目がある。動かないものを動くと書いていない |

出自の確認: 他OS・libc・GUIツールキットのコードが持ち込まれていないか、ライセンス表記・著作権表記・特徴的な識別子を grep し、ログで外部からのダウンロード(curl/wget/git clone)を調べる。フォントの出自とライセンスを確認する。

任意項目(ネットワーク・インストーラー・独自アプリ)は、あれば動作を確かめて別枠で記録する。
